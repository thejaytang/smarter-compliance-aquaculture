# Four-pane workbench delivery | 2026-09-16

## Implemented scope

The existing Workbench now provides source field annotations, four collapsible/resizable panes, six source-bound interpretation fields, separate AI candidate adoption, append-only interpretation history and deterministic checking logic. The user's subsequent API change is included: one shared **Settings → AI service** form for URL, model and write-only key, reused by interpretation generation. No default provider/model is supplied. No separate System3 service, automatic Requirement extractor, Site Model query or actual compliance result is introduced.

[Maintained usage/data contract](../../workbench/docs/requirement-interpretation.md) owns field definitions, endpoints, credential handling and backup/export boundaries.

## Direct browser observations

Using the isolated TS007 synthetic fixture, with workers disabled:

- **Finish & collapse** immediately switched to annotations and showed the anchoring-line Subject alongside the already completed “Farm staff and managers” Subject in another saved session.
- Keyboard activation of a source mark opened the matching Requirement field. Original source text, Markdown and material revision stayed unchanged.
- Six manual fields updated the separate readable checking chain. **Save interpretation**, reload and service restart retained the saved values. The UI preserved unresolved basis/gaps and did not produce an actual Satisfied result.
- Global Settings saved a single local mock endpoint/model. Explicit generation showed destination and material versions; candidate generation preserved formal edits. **Use suggestion** displayed old/new content and references, then allowed manual editing and a separate save.
- Two unsaved Requirement drafts were edited and switched independently. Both exact draft values were recovered on switching and then saved independently.
- Widths 1280, 1440 and 1920 were observed. At 1920 all four panes fit. At 1280 the content workspace scrolled horizontally while the page stayed viewport width. Collapsing the first two panes gave the final two the main space; keyboard resizing worked.
- Native Chrome UI explicitly reported **200%** zoom. At the resulting 735 CSS-pixel viewport, collapse controls, horizontal reading, fourth-pane text editing and Save were usable; saved receipt was observed. Zoom was restored to 100% and the in-app viewport override reset.
- One source-context read was visibly delayed. It completed without losing either draft. The UI now states that it is loading saved source context; source-bound document metadata is cached by reviewer/material/source fingerprint to avoid repeated original parsing. This is not a measured performance guarantee for all document formats.
