## 1. 要达成的结果

在既有水产养殖 Requirement Workstream 中，完成一个可以本地运行、可以冻结版本、主流程实际可用的阶段版本，覆盖 System1、System2A、System2B 和统一人工工作台。同时交付：

1. 与最终冻结版本和样本一致、可复核的质量与稳健性报告，以及机器可读测量数据。
2. 可以实际演示的处理、分流、人工操作、保存、历史、下游重审和输出流程，以及运行和恢复交接说明。
3. 一个可编辑的多页面 Canva 技术演示及可打开链接，逐页讲清全部系统、技术细节、质量证据和局限。展示主件只有这一份 Canva 设计，不增加其他演示格式或平行主版。

不以修复多少 bug、增加多少测试、清空多少队列或画出多少图作为产品完成标准。首先核对实际日常服务已经接入什么、仅在隔离环境验证过什么、尚未实现什么，再补齐主要缺口并测量质量。

首次实施窗口为 6–8 小时，最长 8 小时，从我明确要求开始实施时起算。时间截止意味着停止并交付真实状态，不意味着自动通过。可以冻结一个有价值但范围受限的候选版本，但只要必要验收项未通过，整个目标就保留未完成。后续窗口须由我明确启动。

长期目标仍由[已对齐目标](requirement-workstream-target.md)定义。此前[功能阶段合同](requirement-workstream-stage-delivery.md)和[功能交付报告](../reports/requirement-workstream-functional-delivery-20260910.md)保持其历史效力，复用已经验证的迁移、恢复和人工机制。此前对全面质量的延期不能豁免本轮具体质量测量。大量真实业务 Pending、正式交付 Requirement 为零、用户尚未完成审核，都不直接等于系统功能未完成。工程人员不得代替用户完成真实业务决定，不把做完现有全部来源作为阶段完成条件。

## 2. 保留的系统职责与授权边界

- System1 继续负责来源身份、原件、版本、选择、人工决定、治理历史和后续问题。保留已经完成的来源审核；不扩大来源发现或材料范围；付费、访问、正文不完整等问题保留可操作的 Pending。
- 业务状态和人工决定进入所属关系型数据库，原件、图片和不可变 Canonical 可在受管理文件中保存并关联。不得重做已经验收的数据库迁移，不覆盖原件、Canonical、Gold、历史或恢复证据。
- A 忠实还原全部原文、辅助内容、结构和阅读顺序，不提前筛掉非 Requirement 内容。区分文本页、扫描页和混合区域，检查尚未对应抽取结果的原文区域。扫描正文必须处理；照片和示意图保留整图、图号、图题、位置，本阶段不识别图内文字。
- 表格保留整体原图、标题、表注、脚注、单元格内容、行列、合并关系及跨页联系。A 中的行列属于结构还原，B 才判断 Requirement。继续保留合理的 HTML、XLSX 和受控格式转换路径。
- B 基于已经查验的 A 和必要上下文判断 Requirement，包含建议性要求，同时检查误收和漏判。保留原文依据、编号、来源版本、位置和上下文。完整原编号父项、生成分项、原文编号和计数明确区分。拆分仍按[临时策略](../../system2/docs/contracts/requirement-subdivision.md)可逆、可配置地执行，不能默认为同伴已确认的永久语义。禁止编造要求、错误关联或父子重复计数。
- 所有人工审核、补充、修正、抽查都在同一个正常工作台完成。展示要决定什么、为什么收到、原文证据、上下文、机器置信度依据及未验证范围。内容界面左原文、右结果和上下文。缺失内容能定位、录入并绑定原文。
- 工作台确认完成后，所属数据库保存决定和历史，已解决事项进入 Review history，Excel 后台自动同步。草稿、保存失败、仍有问题或已过时的事项不能显示完成。人工确认不等于机器置信度 100%；实质问题全部解决后，人工可以在机器置信度未知时确认结果。
- Excel 只作查看和交付，不提供修改回写。正常读取和保存不得等待整个 Excel 重写。保留版本、后台合并更新、一致快照、失败重试、最后有效输出，并区分决定已保存、Excel 待同步、已同步和失败。
- 来源、内容或关联上下文变化后，只重查受影响结果，暂停相应下游交付并保留旧版历史。未受影响结果不应无故整体重审。
- 无外部大模型 API 时，本地处理、检查、人工修正和输出仍运行。可选 API 失败时保留结果并返回本地或人工路径。产品运行中的多智能体不得修改原件或人工决定、降低门槛、自改代码或部署；建议必须经过现有程序验证与门槛。
- 保留既有外部行动边界：不提交、推送、擅自发布，不发送保密材料，不擅自启用外部模型、定时机制或扩大检索。服务重启等受保护操作按既有授权处理。之后制作 Canva 时只使用获准且不保密的展示材料；本次目标编写不构成设计创建或材料上传。
- 每周一抽查目标保持 System1 5 条来源、A 20 个原文检查单元、B 5 个正负分类判断，System3 关闭。抽样不足、未完成、发现问题和历史必须可见；测试机制不等于启用实际定时。
- 不实施 System3 ontology、Evidence 提取、Site 匹配或最终合规决定，不扩展到无关重构。可选智能增强不是本轮前置条件，也不能挤占本地基线、主流程和交付时间。

## 5. 逐项验收矩阵

每项保存：对象/范围、精确分子分母与单位、方法/版本、证据路径、资格、PASS/FAIL/UNMEASURED、未通过时的行动。PASS 仅适用于声明的范围和证据类别。关键错误不得被平均分遮盖，自然与植入不能合并。尚未实施的 v2 测量初始全部 UNMEASURED；历史证据只有经版本与依赖相关性检查后才能复用。

16 个固定关键操作场景，可以同一次流程提供多个证据，但逐项记录结果：

1. 正常启动入口/总览，进入 System1、A、B，核实实际连接和运行版本。
2. 查看保留的 System1 人工决定/历史；隔离副本记录来源后续事项，未解决访问或正文问题保持 Pending，不重复纳入审核。
3. 通过受控路径显式处理或复用文本 PDF、完整 HTML、XLSX；打开工作台本身不能新建处理作业。
4. 不完整 HTML、不可用/不支持材料及获准解析副本沿袭进入正确来源/格式操作，原件保留。
5. 发现并定位没有任何输出对应的原文区域，在工作台补录准确内容。
6. 查看/纠正扫描正文，保留图像，区分插图/图题与正文处理义务。
7. 修正表格单元格、网格、合并和脚注归属，保留整体证据和跨页片段；必要时形成一个完整且有原文依据的父项。
8. 保存和恢复草稿，拒绝过时/不完整提交，不显示完成、不丢草稿。
9. 确认已查验 A，保留机器置信度未知，查看保存结果/历史，只解锁相关 B 上下文。
10. 纠正 B 误收和漏判，包括建议性条款，保存原文、原因及前后分类。
11. 添加、修改、撤回临时 B 分项和计数策略，无虚构原编号、上下文丢失或双计数。
12. 隔离改变来源/内容/共享上下文，验证受影响 A/B/交付重审，旧历史和无关结果保留。
13. 重放已保存请求、拒绝冲突/过时请求，中断和恢复测试服务后决定不丢、不重复。
14. 查看 Excel 已保存/待同步/同步/失败，测试锁定或失败后自动恢复，精确对照数据库内容和版本并保留最后有效文件。
15. 隔离生成周检，包含短缺/空总体及发现问题，验证每周一批、A 原文侧、B 正负、未解决后续事项与历史。
16. 关闭 API 完成选定的本地/人工交付；模拟可选增强不可用，不丢结果、不越过门槛。

### Q：量化质量与人工负担，数值全部为工程提案

## 6. Canva 内容和三层架构

同一个 Canva 设计至少覆盖以下 8 组内容，初始建议分成24页，页数可以随可读性调整，但不能删掉内容：

1. 总体架构、材料流、职责边界，严格采用下面确认的上中下三层；System3及外部团队只示本阶段边界。
2. 每个系统内部完整主路径、模块、分支、失败、人工点和阶段流转，拆页展示。
3. 当前实际技术：运行环境、解析/OCR/表格配置、原件、所属数据库、不可变Canonical、修正overlay、版本/依赖、回执、恢复和后台同步；区分代码已有、正常加载、仅提案。
4. 每个系统Excel的作用、实际sheet/状态/字段，以及向下游交接字段和有依据示例。A/B可共用现有工作簿，不新造重复主数据，不回写；父子计数仍标临时。
5. 人工收到什么决定、为何收到、原件和上下文、置信度从何而来、哪些缺校准；人工确认与机器评分分开。
6. 自动解析与自动放行分别如何运作，核查器、门槛、硬阻断及未告警错误检查。不能把全体待审当作安全证明。
7. 工作台如何减负：并排对照、定位、上下文、任务归并、补录、表格修正、草稿恢复、重试、历史、定向重审。已具备机制和实测效果分开。
8. 功能接入矩阵、真实质量/稳健性数字、参考资格、范围限制、故障、人工负担/性能、运行交接与下一步优先级。

已确认的总览必须保持上、中、下三大横向层；上、下层都是跨系统协作层，不是某一个系统的局部步骤：

- 上层：统一人工审查，横向贯穿System1、A、B。标明各系统提交哪些待审信息、原因、原文证据、置信度/未验证范围；人工决定和修正如何返回所属系统，如何改变保存状态、历史及下游重审/输出。向上提交和向下回流分开标注。
- 中层：System1 → System2A → System2B，展示适度简化的内部主路径、交付物和字段组；未来System3只画边界。原件、Excel、Canonical、overlay和详细交接字段在后续页面展开。
- 下层：API连接后的可选多智能体增强，横向贯穿各系统。逐阶段说明增强什么、调用什么现有程序、传入何种证据、返回何种证据或建议。System1可讨论既定来源范围内的证据化来源评估；A可讨论原文限定的抽取/核查建议；B可讨论判断/拆分复核。各项按真实证据标已实现、提案或未验证。API请求和建议回流明确标注。当前API未启用、增强未验证处用图例、虚线和状态标签，与离线核心区分。不得把目标架构画成现有事实。多智能体不能篡改原件/人工决定、降低阈值、自改代码部署；结果仍经程序验证和门槛，失败返回本地/人工。

不把所有内部细节挤进总览。后续页面仍属于同一设计。图形和文字应实际可编辑，不把整页截图当可编辑工程图。展示尺寸文字必须可读，无非预期重叠或截断。连接线起终点和方向语义正确，避开文字/节点，减少交叉；不可避免时清楚区分。箭头细小克制，与节点、字号和线宽比例统一，禁止大箭头扎成团。同类节点、字体、颜色、对齐、留白一致。

后续制作时使用适用的Canva/演示技能；工具已连接不证明其产物正确或可编辑。每页实际渲染查看，保存页ID、版本、重叠/截断/可读性、连接方向/交叉、箭头比例、样式/留白、编辑性、三层语义、问题/修复/复查/最终状态。文字或结构改后重看受影响页。不要擅自增加另一种展示交付。

建议24页安排：1–2目标与三层总览；3–5 System1流程/治理/Excel交接；6–9 A格式路由、PDF/OCR配置、完整结构和原文核查；10–12 B判断、父子计数及门槛；13–15统一工作台、真实修复、草稿历史与重审；16–18运行模块/环境、数据权威/版本恢复、实际Excel与系统字段交接；19–21接入矩阵、自然质量/独立植入挑战、自动化与人工性能；22–24周检/离线/API边界、运行演示、局限与下一步。

## 8. 尝试、再次尝试和调整边界

按“观察失败→区分症状和根因→提出少量可区分假设→最低成本验证→诊断→最小干预→同样本验证”执行。每个根因记录历史报告、尝试号、假设、最小判别实验、冻结前后、未变对照、结果、决策、连续无效次数和重启所需新证据。

无效尝试指既没减少目标错误，也没产生改变诊断的有效证据。负结果若真正排除了假设可以有价值，但须说明，不能玩计数规则。同一失败假设换一种改法不清零；同问题过去尝试必须计入。连续3轮无效后停止该路径，只有新证据改变诊断、有新的有界试验且预算仍在，才恢复。

人工替代路径可保留功能，但不能抹掉质量/自动化失败。数据丢失、错误覆盖、虚假完成或主要流程断路必须修复，或明确作为目标未通过的硬阻断。每节点选CONTINUE、ADJUST、BACKTRACK、PIVOT、STOP，保存范围、证据、失败、未决输入、已用/剩余时间和下一项能改变判断的实验。

近阶段详细，后续按证据滚动调整，不机械重复旧计划。跨session由文档恢复，不重新迁移、不重算历史尝试为零。若需要缩范围，明确具体未达的质量/材料要求，保留用户确认核心功能；不能静默丢难样本、降低阈值或把自动化换个说法视为成功。

实施开始后才创建本轮报告/运行证据，复用既有归属结构。每个指标记录ID、目标版本/采用情况、代码/样本哈希、自然/植入/合成、原始/修正后、参考资格、分子/分母/单位、不确定性、目标值、实测、判定和证据。组件证据保留在所属目录，以链接引用，不生成多个事实主版。不新造独立人工资格。

## 9. 最终完成与停止标准

最终必须分四层回答：功能/完整性、范围内测量质量、安全自动化、交付包。另明确独立总体质量验收资格。开发诊断可以达到自己的范围内提案，但不能说已独立验收；全面校准、大held-out和所有真实扫描不阻止有价值诊断，它们的缺失仍限制相应独立主张和自动放行。

整个v2目标PASS要求：全部强制H/D通过，按完整v2启动所采用且适用的Q阶段目标有充分声明证据通过，包括非零安全自动化目标，除非用户明确改动。启动即采用阶段数值，不需逐项再次确认；生产放行策略仍受原边界保护。

若安全自动放行仍为0、必要质量项FAIL/UNMEASURED或主流程/完整性仍有问题，就写“已冻结受限候选版，整体目标未完成”。只有用户明确调整目标范围，才能将更窄目标认定完成。报告写完、Canva做好、回归全绿、时间截止都不能自动PASS。

到截止时停止，保留版本清单、最后有效候选、未通过项、已试假设、下一项最有价值实验和最小缺口。独立审查员/校准材料、真实扫描、同伴粒度或实际未决范围变更要具体列明，不泛称还需更多工作，也不要求用户先做完全部业务。后续实施或再次窗口等待我的明确指令。
