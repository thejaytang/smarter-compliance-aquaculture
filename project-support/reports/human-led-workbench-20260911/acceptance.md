# Human-led material workbench acceptance

Date: 2026-09-11. Scope: the [activated target](../../design/human-led-workbench-goal.md), rows M1–D1. This is a local engineering delivery, not business review completion, parser accuracy certification or end-to-end structured Requirement completion.

## 1. Delivered behavior

The normal shared workbench opens a material-centered three-pane workspace. System1 remains the source authority. The original is pinned by snapshot and hash; the middle pane is a versioned human effective layer; the right pane explicitly reports **Not connected**. Extract creates a candidate through the existing structural parsers, with no Requirement classification or publication. Opening, reading, saving and confirming do not enqueue extraction. Native-text reading assistance does not populate the middle pane or accept content.

Reviewers can correct text, type, heading level/parent, original numbering, order, split/merge boundaries, tables, merges and notes; add omitted text/table/image content; link original ranges and dependencies; save partial work; compare candidates; retain, adopt or edit/merge; restore historical content as a new draft; and explicitly confirm a complete saved material. Source problems are reported to the existing System1 workflow with server-bound identity and remain completion blockers.

Additive material tables live in the owning System2 workflow database. The original and Canonical layers, legacy effective edits, review decisions, events and one-way Excel output are retained. Explicit legacy import produces a reviewable candidate with original provenance and unresolved issues; it never relabels old decisions as a new human confirmation.

## 3. Validation and recovery evidence

A subsequent 24-test service/processor run covered the final source-annotation change. The final JavaScript suite passed 52 tests, including the final candidate/follow-up/historical status display. Passing counts supplement the browser scenarios; they are not the completion criterion.

The isolated configuration and sample provenance are retained at `workbench/runtime/human-led-acceptance/manifest.json`. It uses a real System1 bridge with isolated owning state and the normal Workbench/MaterialService code, not a fake backend. TS001/TS002/TS003 are synthetic. PA001/CS010 are unchanged bytes copied from registered public originals. All named candidate decisions, source reports and the Excel content confirmation in this report are engineering fixture actions only.

Preservation backups are at `workbench/runtime/human-led-preservation/before/` and `after/`, using SQLite consistent backups and logical table fingerprints. All legacy business tables matched, including original decisions, review-history, policy, deliveries and job state. Two normal browser sessions were added. No snapshot, Canonical artifact, existing human edit or history was deleted. Browser journals preserve unsaved work by reviewer/material/tab; rejected request bodies additionally remain in the owning conflict table.

Two observed integration failures were corrected and retested: native PDF plugin black screen led to the default original page-image reader; real HTTP409 exceptions now expose the protected version-comparison flow. A third correction clears previous material action notices when switching materials. These were actual-browser findings, not reported as successes before repair.

## 4. Entry, runtime and limitations

Use [Open Workbench.command](../../../Open%20Workbench.command), then **Materials → Open materials**. The normal local origin is `http://127.0.0.1:62742/`; [normal load evidence](normal-loaded.json) records PID 21058, its actual roots and a current parent-source fingerprint. UI modules are served on request; reload an already-open page after changes. The normal state has 38 available sources and 0 opened new material workspaces. Existing 87 source records, 30 pending source tasks and legacy histories retain their business meaning; no queue was cleared for engineering acceptance.

The isolated acceptance service is stopped after verification; its files and recovery evidence remain. It can be recreated/read using the [documented isolated workflow](../../../system2/docs/contracts/human-material-workbench.md). The normal service stays running.

The PDF default is full-range paging with scrolling/zoom inside the original page image. Copying uses separately labelled unverified native-text assistance where available; raster pages have no selectable text and no OCR was run. The optional browser PDF plugin remains environment-dependent and is not a passed capability. HTML strips active/external content and may lose assets/layout; intact originals remain downloadable. Excel preserves stored cells/addresses/merges and formula/cache distinctions without calculation or native styling claims. Legacy XLS uses an explicit source/manual compatibility path. Historical native Office acceptance remains deferred.

The exact nested Requirement schema, final form fields, semantic processor and complete structured Requirement workflow are explicitly deferred pending the user's specifications. No model/provider, new schedule, external transmission, publication, commit/push or usage-reset credit was activated. The earlier automatic-quality failures remain historical unresolved results, not newly passed gates.
