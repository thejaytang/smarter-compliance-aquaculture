## Implemented boundary

`system1.governance_store` owns relational sources, operations, append-only before/after history, immutable artifact fingerprints and source-version links. Writes require a bound database view and a matching database revision. Deletions, stale saves, direct Excel readback and altered original-version identity fail closed. Normal record positions remain stable in the compatibility view; this is an implementation constraint, not a requirement granularity policy.

Migration and backup construct a private database and publish it exclusively only after integrity and companion checks. Interrupted migration leaves no usable database at the target; a byte-identical immutable input companion permits retry. The register and managed original inventory are rechecked before publication. Tests inject interrupted import, concurrent source change and damaged backup templates. Recovery copies preserve history and can be modified without changing the live candidate.

The optional local `governance_db` configuration selects the new authority. Existing domain operations use in-memory compatibility views over it; the derived Excel file is not their input. Source replacement retains the former stored path as well as archive copies in database mode. Confidence remains in System1's existing owning assessment database, included by a logical version digest in source export/handoff guards.

System2 now supports handoff schema 2 with `registry_kind=sqlite_snapshot` and a committed state digest. It obtains source eligibility through System1's owning adapter. Corrupting or deleting derived Excel cannot change this handoff; a changed logical source/assessment version invalidates a prior guard. Existing workbook-mode contracts remain supported. New source contract fields identify the digest kind explicitly; an Excel-file hash is not fabricated.
