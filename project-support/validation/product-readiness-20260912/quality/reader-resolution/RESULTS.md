# Bound PDF reader resolution

Reader `material-reader/8` and the existing Workbench reader route now accept bounded physical pixel requests. No parser, dependency, model, business state or original was changed. Existing PDF point dimensions and default scale are retained. HTML reading output is unchanged by this patch. The full parser `/6` regression had reached its terminal result before these edits; its two environment-related file-read failures remain separate evidence, not a passing current reader regression.

## Verification

- 41 System2 reader/parser/navigation/performance tests passed in the component environment, including 17 new resolution cases. Eleven isolated real-HTTP boundary tests passed in Workbench's own environment. Exact commands, temporary root, source hashes and logs are in `start.json`, `receipt.json`, `system2.log`, `system2-junit.xml` and `workbench.log`.
- A two-page real PDF remains byte-identical. Exactly the requested second page is rendered once per resolution; native text, page count, source digest and PDF point geometry remain exact. Default 612×792 pt yields the prior 918×1188 px. Requested widths 1536 and 2304 produce those actual widths without a limiting flag.
- Four real PDF aspect ratios exercise the 32768 px request cap: portrait, landscape, square and 10×2000 pt extreme portrait. Actual PNG dimensions stay within 4096 px per side and 12,000,000 total pixels. Source aspect ratio is preserved subject to integer pixel rounding; requests above these effective limits are flagged.
- Invalid/non-integer/bool requests fail before original/cache access. HTTP blank, duplicate, malformed and oversized values fail before the reader adapter is called. Valid requests forward exact integer page/width options and never call Extract.
- Widths 1000 and 1001 share the normalized 1024 px cache but retain their own request metadata. Source tampering is rejected even on cache hits. Damaged cache JSON rebuilds correctly and a reader version change produces a different cache entry.

Limits and return fields are maintained in the owning [material contract](../../../../system2/docs/contracts/human-material-workbench.md). Byte recovery points and original hashes are in `prechange-*` and `prechange.json`; restore only the reader/server change with review, since later integration may add independent HTML display work. Tests were isolated in a dedicated temporary root. These checks do not establish browser fidelity, new normal-service loading, independent extraction quality or Windows acceptance. Browser integration belongs to the root/reader UI task.
