## Open the workbench

For a new computer or a missing environment, start with [ENVIRONMENT.md](ENVIRONMENT.md). It covers component environments, dependency files, setup, native tools and verification.

Double-click the [workbench launcher](Open Workbench.command). It starts the local service and opens the default browser; repeated launches reuse that service. Select a named reviewer and open **Requirement Extraction System → Pending materials**. The three panes read the saved original, edit full original content and reserve future structured Requirements. **Extract** produces a separate candidate; **Save material** saves a personal partial draft. **Review my changes** and explicit adoption update the main version; **Confirm master content review** requires a separate full-scope human check. **Process** is disabled because the final structure and processor are not connected.

**Source Management System → Pending review / Source records / Review history** opens the independent source workspace for scoring, authenticity, scope, link/file issues, new candidates, replacements, inspections and re-review. A missing valid original prevents INCLUDE. The coordinator uses a visible preview and **Confirm and apply**; colleagues save proposals for return. **Legacy review** and **Legacy history** preserve older extraction access; legacy decisions do not become new material confirmations. Originals and Canonical artifacts are immutable. Excel registers remain one-way generated views. See the [workbench guide](workbench/USER_GUIDE.md), [material interface contract](system2/docs/contracts/human-material-workbench.md) and [current integration state](PROJECT_STATE.md).
